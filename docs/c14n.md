# Canonical XML

`xmlz.c14n` produces the canonical form of a whole document as defined by
[Canonical XML 1.0](https://www.w3.org/TR/xml-c14n),
[Canonical XML 1.1](https://www.w3.org/TR/xml-c14n11), and
[Exclusive XML Canonicalization 1.0](https://www.w3.org/TR/xml-exc-c14n).

```zig
var document = try xmlz.dom.Document.parse(allocator, source, .{
    .keep_comments = true,
    .keep_pis = true,
});
defer document.deinit();

const canonical = try xmlz.c14n.canonicalize(allocator, &document, .{
    .comments = true,
    .exclusive = true,
    .inclusive_prefixes = &.{ "dsig", "#default" },
});
defer allocator.free(canonical);
```

## Behavior

- Namespace declarations are ordered lexicographically by prefix (default
  namespace first), and declarations already in effect from an output ancestor
  are suppressed.
- An element without a default namespace emits `xmlns=""` when an output
  ancestor has a non-empty default namespace.
- Attributes are ordered by namespace URI, then by local name; unprefixed
  attributes (empty URI) come first.
- Empty elements are expanded to start/end tag pairs.
- Character data escapes `&`, `<`, `>` and `#xD`; attribute values escape `&`,
  `<`, `"`, `#x9`, `#xA`, and `#xD` using uppercase hexadecimal character
  references.
- Comments are omitted unless `Options.comments` is set. Processing
  instructions are always rendered.
- PIs and comments before the document element are followed by `#xA`; those
  after it are preceded by `#xA`. No leading or trailing newline is added.
- The XML declaration and document type declaration are omitted; entity
  references are already expanded and CDATA sections are already merged into
  character data by the DOM.
- DTD default attributes are part of the DOM and therefore appear in the
  canonical form.

Exclusive mode renders only namespace declarations visibly utilized by the
element name or one of its attributes, plus any prefixes in
`Options.inclusive_prefixes` (`#default` selects the default namespace).

## Scope

The input is a whole document, which is the octet-stream form required by the
specifications. Document-subset inputs (XPath node-sets) are not supported yet;
they additionally require `xml:base` fixup and propagation of simple
inheritable attributes (`xml:lang`, `xml:space`). For whole documents the
Canonical XML 1.0 and 1.1 forms are identical.

## Differential verification

```sh
zig build c14n-diff
```

The step canonicalizes a corpus covering namespaces, undeclarations, DTD
defaults, comments, PIs, escaping, Unicode, and exclusive-mode namespace
selection, then compares the bytes with libxml2's `xmllint`. Expected output:

```text
69/69 canonicalization differential checks passed
```
